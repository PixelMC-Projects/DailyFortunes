# 抽签模组 · 已确认玩法

记录日期：2026-10-26。本文保留确认的玩法口径；当前实现和验收边界见 README 与 verification.md。

## 每日抽签

- 当天首次成功登录获得一次抽签资格。手持抽签桶右键消耗资格，取得「未解之签」；对解签龛使用后得到签笺。
- 默认按 `Asia/Shanghai` 时区，在当地日期 0 点刷新；时区可配置。跨日仍在线的玩家也能取得当日资格，无须重新登录。
- 每名玩家每天一次；漏掉的日期不补发，未用次数不累计。假人不参与领取和玩家档案。
- 日期按抽取日期记录，不随解签或归档日期改变。不同日期允许抽到同一签。
- 吉凶只影响签文、等级标识与收藏，不发物品奖励，也不施加增益或减益。
- 默认 60 支签等概率，每支权重为 1；保留每支签独立配置权重的能力。
- 等概率时：上上 6/60，上吉 18/60，中平 24/60，小凶 10/60，下下 2/60。
- 配置放在服务端根目录的 `config` 下，不放在存档的 `serverconfig` 中。模组子目录名随工程命名确定。
- 丢失后允许补领自己已经抽取、尚未归档的签；恢复原结果，不能重抽。已归档的签只在藏签匣中查看。

## 合成与物品

- 使用容易获取的原版材料，不依赖其他模组。
- 抽签桶偏重竹子、木材；解签龛采用木材、铜锭、纸；藏签匣采用箱子、纸、铜锭。
- 上述材料方向与低门槛原则已确认，具体数量和格位在实现时据此确定。

## 藏签匣

- 玩家查看自己的收藏。大箱子风格的 9 × 6 格界面，中间 7 列按周日到周六组成月历，两侧用于导航。
- 不另设星期标题，原箱子标题位置显示年月，例如 `2026/10`。
- 打开时自动归档背包中属于自己的已解签笺，旧日期签笺进入对应日期。
- 没有签的日期使用半透明签笺图案；月份外的格子不冒充当月日期。
- 不做赠送和取出。归档后永久收藏，必须确认存储成功才消耗实物。
- 收藏按玩家 UUID 持久保存；破坏匣子不删除收藏，不依附于某个方块的物品栏。
- 放置者可选择一张已收藏签笺展示，固定朝向抽屉正面，签笺下沿悬在匣盖正上方，留少量间隙。
- 解签龛和藏签匣的选中框、碰撞箱贴近木作主体和屋顶；外伸花草不扩大碰撞体积。
- 展示带金色描边，被墙壁遮挡时不可透视；不能直接使用原版穿墙的发光效果。
- 瞄准展示物时显示签文信息，效果参考机械动力护目镜的信息浮层；不依赖机械动力。
- 该信息浮层使用专门绘制的风格化背景，文字实时渲染；不采用默认黑色提示框。配套木铜纸面背景已保存于 `qianjian_ui\hover_v1`，已接入客户端渲染。
- 展示物是装饰渲染，不生成可拾取的掉落物实体。

## 文本与颜色

- 诗句、解签用淡灰色；浅色阅读背景使用相应的深灰褐色以保证可读性。
- 「第三签 · 上上签」整行随等级配色：上上金，上吉绿，中平青蓝，小凶橙，下下朱红。
- 署名行的玩家名用黄色，「所得」和日期用金色。
- 不因聊天粘贴产生的加粗而强制为正文加粗，整体配色克制。
- 六十签第二版采用意象寄意，解签再解释处境与取舍。编号和等级不变，以确认后的第二版作为内置默认配置。

## 数据库与后续讨论

- 用户提出复用称号数据库体系；已核对本地源码，MemorialTitles 使用 MariaDB。
- 建议复用同一 MariaDB 实例，为抽签另建逻辑数据库和受限账号。抽取、解签、补领、收藏等记录独立管理，不与称号表共用迁移版本或玩家删除规则。
- 本地存储与 Manager 接口已实现；本次新模组只交付客户端验收，线上尚未建立抽签业务库。新库的本地与异地备份必须显式加入现有任务，不能假定现有称号备份会自动覆盖。
- 实现时采用后台限流读写、事务和唯一约束，数据库不可用时保留物品与资格，避免阻塞游戏线程。
- 建议抽取时固化结果与签文版本，改权重不重抽旧记录；补领须有记录校验以避免旧副本重复使用。
- 已按后续确认接入 PixelMC Manager 插件接口；已有服务更新暂存到下次重启生效，DailyFortunes 功能默认关闭，待客户端验收后另行启用。
